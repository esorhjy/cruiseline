# 本機行程草案第三階段

日期：2026/11/7。Build：`2026-11-07-planner-v1`。本機實作與驗收；本輪未提交、推送或驗證正式部署。

## 使用方式

1. 航程選日期，點「調整行程」，每段才出現「替換／時段／移動」。閱讀模式不增加一排編輯控制。
2. 保留原安排或選餐廳、設施、表演／活動、休息；候選顯示位置、資格與來源。餐飲合併卡拆成具體實體選項，活動沿用場館／資格版本分組。替換後時間先成為「時間待確認」，自行填12:30或早餐後，不套用歷史時間。
3. 選日期與當日時段，再選「放在哪段前面」或最後。用清單順序排列，不自動把自由文字時間當成可計算排程；不提供拖曳或衝突／交通時間自動估算。可勾選彈性備案。
4. 儲存後只改本機，原38段ID不變。新主卡／餐廳菜單直達，原正式全文留在收合內容。已確認預約與全員演練須另勾確認；草案不代表預約變更或免除出席責任。
5. 「草案與備份」可匯出、選檔匯入、復原上一步、整份還原；每段有「還原這段」。行前準備也保留收合入口。復原保留最近20次本分頁操作，刷新不保留復原歷史，但草案會保存。
6. 匯入先顯示目前與匯入版本差異，明確確認後才取代整份本機草案；取消與錯誤檔不改原記錄。已確認項目的匯入也須確認。匯出檔可交回專案核對，不能直接改GitHub或船方訂位。

## 資料與保護

- `itinerary-planner.js`負責候選轉接、差異套用、JSON驗證與逐欄衝突；`planner-ui.js`負責儲存、編輯dialog、匯出匯入。保留classic scripts，不拆data.js、不加套件、後端或API。
- 唯一新儲存鍵為`dcl_itinerary_draft_v1`。與清單、樓層、搜尋狀態分開；跨裝置、不同網域、不同瀏覽器不自動同步。正式使用建議固定HTTPS網址。
- 格式`dcl-itinerary-draft`、schemaVersion=1、tripId=`disney-adventure-2027-01-25`。檔案上限256KB，嚴格驗證欄位、字數、位置、布林值、識別碼；不接受任意正文／HTML。僅存編輯欄位和原值指紋，不複製全站資料。指紋用於版本差異，不是安全簽章。
- 正式版本同欄更新時，只暫停有衝突欄位，其他變更保留。提供逐項「採用正式／保留草案」，原事件或候選已移除則不能強行套用。移動欄位另比對全站日別／時段結構，避免新版時段插入後錯置。
- 儲存失敗保留本分頁記憶並明示未保存，可立即匯出；讀取到損壞JSON時不自動覆蓋，允許匯出原記錄，再明確重設。另一分頁有變更時阻止後續直接寫入，先匯出或明確載入最新記錄；不實作即時共同編輯。
- 確認狀態對照缺漏時停用編輯，回到正式閱讀模式，不清除草案。搜尋仍索引正式內容；行程結果加正式來源說明，跳轉依穩定ID找目前草案日別。
- 日期標題下仍可查看原正式「當日安排重點」；有草案時時段標題不再顯示舊版動線說明。正文、資料ID、清單勾選、活動原記錄和完整菜單均未改寫。
- 新scripts納入核心快取，build meta、runtime、版本參數及SW一致。離線可編輯與匯出；活動可查不代表航次可參加，餐點仍走既有lazy load、retry與runtime cache。
